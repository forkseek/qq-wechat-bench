# QQ 与微信共存工作台：GitHub 选型

调查日期：2026-10-14，北京时间。先调查与审查源代码，再决定正式接入；本记录不把项目作者的兼容性声明当作本机实测成功。

本页记录最初选型及静态审查阶段。后续已复用微信 SDK、Pino 和 node-cron，实现工作台 0.4.0；实机及测试结果见 [双平台验证记录](双平台验证-2026-10-14.md)。QQ 桌面补丁经用户选择暂不安装，保留原 NapCat Shell 采集；下文“尚未执行”描述均指最初调查阶段。

## 已确认的新需求

- QQ 与个人微信同时存在于同一个工作台。
- 用户正常登录本机客户端后，工作台自动发现账号并接入；后续浏览会话、发送文字、图片和文件。
- 增加日志，以及定期处理本机 SQL 数据的功能。
- 优先复用 GitHub 项目。
- 现有 QQ 实验范围保留；“发现已登录账号”与“将哪些聊天保存及交给 AI”分开配置。

本机只读核对：QQ `9.9.20.36330`，微信 `4.1.13.65`。现有项目是 Node.js 24 + SQLite，当前代码版本为 `0.3.0`，已有 QQ 看护、补拉与 AI 批次处理，不能按初次搭建时的 `0.1.0` 重写。

进一步解包审查发现：这个固定版本的 Framework ZIP 顶层是 `napimain.exe`、`napiloader.dll`、`nativeLoader.cjs`、`napcat.cjs` 等原生加载入口，没有 LiteLoader 插件的 `manifest.json`。因此不能直接将它当作已经验证可导入 LiteLoader 的插件。QQ 桌面接入仍须核对实际加载方式与当前客户端兼容性。

LiteLoaderQQNT 当前安装文档要求 QQ 文件校验补丁或频道内 DLL；其公开安装脚本会修改 QQ 启动入口并修补可执行文件。这与新增一个普通工作台接口不同，必须先准备准确的文件清单、备份和恢复步骤，不直接执行一键脚本。参考：[安装文档](https://liteloaderqqnt.github.io/guide/install.html)、[公开安装脚本](https://github.com/Mzdyl/LiteLoaderQQNT_Install/blob/main/install_windows.py)。

## 微信候选源码审查要点

- `WeChatDB` 可以显式指定 `keys_file` 与 `workdir`；接入时将密钥和解密缓存放在本工作台私有数据目录，保持微信源库只读。
- 当前 SDK 默认启用文件日志，接入前要关闭其默认日志及可能暴露敏感信息的控制台诊断，统一通过工作台记录经过筛选的事件。
- 当前 SDK 通过“最近修改的数据库目录”初选账号，不能单凭缓存存在认定当前登录账号；需要验证活跃登录进程及数据库密钥是否对应，避免把旧账号识别为在线账号。
- `guia` 默认将布局配置写到用户主目录；接入时显式改到工作台自己的数据目录。
- 新版消息的 `local_id` 不是跨分片唯一标识，去重必须包含平台、账号、会话、`shard` 和消息编号，不能只用 `local_id`。
- 同名联系人与群聊要按真实平台标识定位；发送前核对目标，超时后先核查发送记录，避免盲目重试。

这些是实际读取源码发现的集成要求。截至本记录，微信候选源码已下载审查，QQ Framework 包已解包审查；尚未安装或执行这些接入组件，也未修改正式服务代码或原客户端安装文件。官方微信已打开，等待用户正常登录后进行兼容性验证。

## 自动发现规则的实现边界

普通客户端正在运行，不代表账号已经登录，也不代表消息桥已经可用。状态至少分为：发现客户端、等待登录、接入中、可以收发、接入失败。一次初始化接入组件后，常驻工作台负责自动检测账号与恢复连接。

QQ 需要把桌面接入组件装入同一 QQ 客户端；继续单独运行 Shell 再登录同一账号不能满足新规则。微信候选可沿用本机微信登录状态，但其数据库读取需本机登录进程提供密钥，密钥只允许本机受控保存，不能写进日志或发送到模型。

界面统一，但数据库按平台、账号、会话、原消息标识隔离。文字、图片和文件发送由用户点击触发，记录待发送、成功、失败、结果不确定等状态；超时不能直接自动重发，以免重复发送。

## 日志与本机 SQL 的建议范围

日志包含客户端发现与登录变化、连接恢复、收发结果、AI 批次结果、定时任务开始结束和错误；支持按平台、级别和时间查看及保留期限。

定期 SQL 处理分为消息整理与数据库维护：前者按新消息游标整理并复用已有失败重试，后者定期一致性备份、检查、WAL checkpoint 与 `PRAGMA optimize`。默认不自动删除原始聊天；数据库维护仅针对工作台的 `workbench.sqlite`，微信源数据库保持只读。

备份复用 [Node.js SQLite backup](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)，维护操作遵循 [SQLite PRAGMA 文档](https://www.sqlite.org/pragma.html)。复制正在运行的主 `.sqlite` 文件不能替代一致性备份，因为 WAL 中可能仍有未合入的数据。
