# 微信群添加与验证记录

版本：0.5.1。已更新本机 `http://127.0.0.1:4318/` 的工作台。

## 使用方式

1. 正常登录电脑微信。
2. 在“会话管理 / 拉取的群聊”点击“添加群聊”，选择“微信群”。
3. 搜索群名，核对群标识后点击“添加”。首次读取最近的本机消息，之后沿用微信轮询和 AI 整理队列。
4. 已添加的微信群与 QQ 群一起显示，并标注平台；点击“移除”后停止保存新消息，已保存的消息与待办保留。

列表来自当前电脑微信的最近会话，最多读取 200 个会话。找不到目标群时，先在电脑微信打开该群，再点击“刷新列表”。这不是创建或加入新群的功能。首次消息读取沿用原有接口，默认最近 80 条，不代表导入全部历史记录。

## 实现

- `GET /api/wechat/groups`：只读取当前登录账号的会话元数据，过滤私聊、公众号与其他账号；不会因为打开选择器而保存聊天正文或调用 AI。
- `POST /api/wechat/groups`：提交 `conversationId`。添加前重新核对当前账号和原生群编号，同名群各自独立；拒绝私聊、未知会话和旧账号的群。
- 关注设置保存在现有 SQLite 会话表，沿用消息去重、来源证据、后台增量保存和待办分析；没有另建一份微信群配置。
- 首次读取失败时返回“已添加，等待读取”的明确结果，保留已保存的设置，后台继续尝试。新增数使用数据库总数计算，不受消息页 80 条限制。
- QQ 群列表、手填 QQ 群号、原有采集范围与桌面 QQ 优先保护继续使用原接口。
- 前端防止切换平台时较晚返回的旧列表覆盖当前平台，搜索仅作用于弹窗中的条目。

## 验证

- 完整测试 71 项通过，0 失败；34 个 JavaScript 文件语法检查以及 JSON 默认配置、版本、锁文件校验通过。
- 新增 5 项隔离测试：当前账号和群类型过滤、同名群独立、精确添加及重复去重、移除与恢复、旧账号与离线状态、首次读取失败、历史超过 80 条时的新增统计。
- 独立浏览器在模拟账号环境验证了 QQ / 微信切换、搜索无结果、指定同名群添加、群卡片显示、移除保留消息与恢复入口；没有发送消息，页面 JavaScript 错误为 0。
- 实机更新后微信在线，添加弹窗显示当前账号的 45 个微信群，并具备平台切换、搜索和刷新控件。发现列表会随微信最近会话变化，既有会话元数据数量不等同于当前可选群数量。
- 真实账号仅验证列表读取，未代选任何群：已关注微信群仍为 0。真实消息 80 条、待办 19 条、发送记录 6 条，均与更新前一致；SQLite `quick_check=ok`。
- 连接、QQ 采集、模型三份私有 JSON 配置的 SHA-256 均与更新前相同；QQ 保持 `desktop_in_use`、独立采集常驻关闭。更新前记录的 15 个 QQ / 微信进程均保持原 PID 和创建时间。

本机数量、配置哈希与进程对照保存在已忽略的 `data/verification/wechat-groups-deployment-before.json`、`wechat-groups-deployment-after.json` 和 `wechat-groups-clients-before/after.json`，不包含聊天正文或密钥。
