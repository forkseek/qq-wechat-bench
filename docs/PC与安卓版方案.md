# 讯课 PC 版与安卓版方案（草案）

2026-10-13。这一版只写方案，确认后再动手。

## 0. 已经定下的

| 事项 | 决定 |
| --- | --- |
| 常驻登录的 QQ | **小号**。小号加入通知群后由 NapCat 常驻登录；主号照常用桌面 QQ |
| AI | **在线 API**，例如 DeepSeek 这类兼容聊天补全接口的服务。具体模型在配置时选 |
| 进度 | 先出方案，你确认后按第 9 节的顺序分步做 |

## 1. 总体结构：一台主机，两个客户端

```
            ┌──────────────────── PC 程序 ────────────────────┐
QQ 小号 ──> │ NapCat ──> 主机服务（收消息 / 补拉 / 存储 / AI / 提醒）│
            │                 │                              │
            │            PC 窗口界面                          │
            └─────────────────┼──────────────────────────────┘
                              │ 同一 Wi-Fi 或私人组网（扫码配对，带设备密钥）
                              ▼
                         安卓 App（同一套界面 + 手机本地提醒 + 离线缓存）
```

- **主机服务**就是现在 `server.mjs` 和 `lib/` 的升级版，负责所有「干活」的部分。
- **界面只写一套**（现在的 `public/`）。PC 窗口和安卓 App 共用它，只是连接的主机地址不同。
- **安卓版不能脱离电脑独立运行**：NapCat 不支持安卓，安卓上收不到 QQ 群消息。读取手机 QQ 的通知栏也不可靠：开了免打扰的群不弹通知，长消息会被截断，多条还会合并。
- 以后如果想让电脑关机也不影响，可以把主机服务搬到一台云服务器上（见第 2 节方案 C），两个客户端不用改，只换一个地址。

## 2. 安卓版的三种做法

| | A. 连电脑上的主机（推荐） | B. 安卓完全独立 | C. 云服务器做主机 |
| --- | --- | --- | --- |
| 怎么收 QQ 消息 | 电脑上的 NapCat | 收不到（见上） | 云服务器上的 NapCat |
| 电脑关机时 | 手机能看缓存，提醒照常；收不到新消息 | — | 不受影响 |
| 额外花费 | 无 | — | 每月服务器费用 |
| 数据在哪 | 你的电脑 | — | 云上 |
| 复杂度 | 中 | 不可行 | 高（Linux 部署和运维） |

推荐先做 **A**。主机服务和界面分开设计，以后想换成 C 时，只需要把主机部署到服务器上。

## 3. 两端的功能对照

| 功能（现有） | PC 程序 | 安卓 App |
| --- | --- | --- |
| 待办清单：新增、修改、完成/恢复、取消、筛选、搜索 | ✓ | ✓ |
| 待办详情：来源原话、修改记录、AI 的待确认问题 | ✓ | ✓ |
| 消息流 | ✓ | ✓ |
| 会话管理：关注 / 停止关注、名称与整理规则 | ✓ | ✓ |
| 我的信息与长期规则 | ✓ | ✓ |
| 通知助手（AI 对话） | ✓ | ✓ |
| 状态：QQ 是否在线、AI 是否配置 | ✓ | ✓（只读） |
| QQ 扫码登录、暂停 / 恢复采集 | ✓ | 只能暂停 / 恢复 |
| AI 服务设置（填写和测试 API Key） | ✓ | — |
| **新增**：截止提醒 | Windows 通知 | 手机本地提醒，电脑关机也会响 |
| **新增**：离线查看 | — | 显示上次同步的数据 |

## 4. 第 1 步：PC 程序

用 **Electron 44** 做外壳。它内置 Node 24.21，和现在运行工作台的 Node 一样，现有的服务端和数据库代码可以原样放进去。

### 4.1 常驻

- **托盘**：关闭窗口只是缩到托盘，不会停止服务。托盘菜单有：打开、QQ 状态、暂停 / 恢复采集、退出。
- **开机自启**：放在设置里，默认关闭，由你自己打开。它用的是 Windows 当前用户的「开机启动项」，不需要管理员权限，关掉开关就取消。
- **退出程序**：同时停止 NapCat，让小号下线。（待确认，见第 10 节）

### 4.2 看护 NapCat

- **免扫码**：启动 NapCat 时带上小号 QQ 号，用本机的登录记录快速登录。只需要第一次扫码。偶尔 QQ 风控会要求手机确认，这时程序弹出扫码窗口并发出通知。
- **自动恢复**：NapCat 自己会重启崩溃的内部进程、掉线后会重新登录（已经从它的源码确认）。但它在 10 秒内崩溃 3 次就会整个退出，所以主机每 60 秒检查一次，发现不在就重新拉起。重试间隔依次为 1、2、5、10 分钟，避免反复重启。
- **暂停采集时**不会自动拉起。

### 4.3 消息补拉

- **触发时机**：程序启动时；QQ 从离线恢复在线时（重新登录、电脑睡眠唤醒）；每 30 分钟兜底一次。NapCat 推送失败不会重试，靠这一步补上。
- **做法**：调用 NapCat 的群历史消息接口，从最新一条往前翻页，每页 20 条。遇到已经保存过的消息就停，最多翻 10 页。
- **去重改用群内序号**：每条群消息都有一个全群统一的序号（NapCat 里叫 `real_seq`），主号和小号看到的是同一个值。以后用「群号 + 序号」识别同一条消息，补拉和实时推送就不会重复，换账号也不会。

### 4.4 换成小号的迁移

1. 你先让小号加入群 `<YOUR_QQ_GROUP_ID>`，可能需要管理员审核。
2. 会话的编号改成只看群号（现在是「登录账号 + 群号」）。这样换账号后，消息不会被拆成两个会话。
3. 已有的 19 条消息是旧版本存的，没有记录序号。迁移时按「发送者 + 发送时间 + 内容」和小号补拉回来的消息对齐，避免重复。
4. 小号在程序里扫码登录一次。之后停止旧的主号采集，主号就可以正常用桌面 QQ 了。
5. 迁移前自动备份数据库。

### 4.5 AI（在线 API）

- **你需要准备**：在服务商注册账号、充少量余额、创建一个 API Key。
- **设置页**里填写服务地址、模型名和 Key，并新增一个「测试连接」按钮。Key 用 Windows 自带的加密存储保存，不写成明文文件。
- **隐私**：所关注群里的文字会发给服务商。
- **费用**：按用量计费。通知群消息量不大，具体以服务商价格为准。
- **建议加一条会话规则**：从已采集的消息看，这个群大多是每天的「@全体成员 记得签到」。可以在会话规则里写明「每日签到提醒不建任务」或「当作每日重复事项」，避免每天生成一条一样的待办。

### 4.6 Windows 通知

- AI 整理出新待办，或者有待确认的事项时通知你。
- 截止提醒：默认截止前一天 20:00 提醒一次，截止当天提前 2 小时再提醒一次。时间可以在设置里改。

## 5. 第 2 步：让手机能连上主机

- **默认不对外**：只有你在 PC 程序里打开「允许手机连接」后，主机才对局域网开放，否则仍然只允许本机访问。第一次打开时 Windows 防火墙会弹窗，需要你选择允许。
- **扫码配对**：PC 程序显示一个二维码，里面是主机地址和一次性配对码（5 分钟内有效）。手机扫码后，会得到一个只属于这台手机的设备密钥，之后每次请求都要带上它。在 PC 上可以随时撤销某台手机。
- **增量同步接口**：手机只拉取上次同步之后变化的待办、消息和会话。修改待办时沿用现有的版本号冲突检查，在两端同时改同一条待办时，不会互相覆盖。
- **连接方式**（待确认，见第 10 节）：
  - **同一个 Wi-Fi 直连**：不用装别的东西。但要注意，校园网和公共 Wi-Fi 通常不让同网设备互相访问，手机可能连不上电脑；而且局域网内的传输没有加密。
  - **私人组网（Tailscale 等）**：电脑和手机各装一个，登录同一个账号。传输是加密的，在宿舍、教室、家里都能用。在国内的连接速度需要实测。

## 6. 第 3 步：安卓 App

- **技术**：用 **Capacitor 8** 把共用界面打包成 App，再补上原生能力：
  - **扫码配对**：选不依赖谷歌服务的扫码组件，因为国产手机大多没有谷歌服务。
  - **截止提醒**：用手机本地的定时通知。Android 12 以上需要你允许「闹钟和提醒」权限。
  - **后台同步**：安卓规定后台任务最短 15 分钟一次。同步到新待办或待确认事项时发通知。
  - **离线缓存**：保存最近一次同步的数据，没网也能看。
- **国产系统设置**：要允许通知、允许自启动或后台运行，并关闭电池优化，否则后台同步和提醒可能被系统杀掉。App 里会给出对应的设置引导。
- **安装**：APK 直接安装，不上应用商店。手机上需要允许「安装未知应用」。

## 9. 分步计划和验收标准

| 步骤 | 内容 | 做完的标准 |
| --- | --- | --- |
| 0. 准备（你来做） | 小号进群；注册 AI 服务并拿到 API Key | 小号能在 QQ 里看到群消息；有一个可用的 Key |
| 1. PC 程序 | 第 4 节的全部内容 | 开机后在托盘自动运行；小号不用扫码就能登录；手动结束 NapCat 后 1–2 分钟内自动恢复；程序关闭期间群里的消息，重新打开后能补回来；配好 AI 后，新通知自动出现在待办里；安装包能在本机装上 |
| 2. 远程访问 | 第 5 节 | 手机扫码配对成功；没配对的设备访问被拒；在 PC 上撤销后，手机立即失效 |
| 3. 安卓 App | 第 6 节 | 第 3 节表格里的功能都能用；断网能看缓存；锁屏状态下截止提醒按时弹出；后台同步到新待办后有通知 |

每一步都会补测试，做完在真机上验证一遍再进入下一步。

## 10. 需要你确认的问题

1. **手机连接方式**：只用同 Wi-Fi 直连，还是用私人组网，或者两种都支持？我建议两种都支持，默认用私人组网，因为校园网大概率不让手机直接连电脑。
2. **退出 PC 程序时**是否同时让小号下线？我建议是。平时关窗口只是缩到托盘，不影响采集。
3. **截止提醒的默认时间**：前一天 20:00，加当天提前 2 小时，这样可以吗？
4. **手机的品牌和安卓版本**：用来写后台运行和通知权限的设置引导。
5. **小号**是否已经加入通知群？

## 11. 风险和限制

- 小号用第三方工具登录，有被限制甚至冻结的可能。这也是选小号的原因：风险不会落到主号上。
- QQ 或 NapCat 更新可能导致暂时不兼容。程序会固定使用当前的 NapCat 版本，升级前先备份。
- 安卓上的新待办通知不是实时的，大约 15 分钟一次。群消息本身由手机 QQ 实时提醒。
- 电脑睡眠或关机时收不到新消息，醒来后会自动补拉。
- PC 安装包没有签名，第一次运行会提示「未知发布者」。
- AI 可能会理解错。所有 AI 整理的结果默认标为「待确认」，并保留来源原话，方便核对（现有机制）。
