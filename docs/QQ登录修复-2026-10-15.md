# QQ 桌面登录修复 · 2026-10-15

版本：0.4.1。

## 实际问题与恢复

排查时，桌面 QQ 与工作台启动的 NapCat Shell 同时存在；最新采集日志提示“账号已登录，无法重复登录”。常驻开关保持开启，自动拉起没有检查桌面客户端。停止采集后，桌面仍提示重复登录。

普通进程命令未真正结束两个残留 QQ 实例；WMI 查询仍能找到它们。按官方 QQ 可执行文件及创建时间核对后，调用系统进程终止接口，两次返回成功，重新查询确认残留已消失。用户重新打开官方 QQ 后确认“已进入 QQ 聊天主界面”。没有清除账号、登录缓存或聊天数据。

官方文件哈希与先前备份一致，未安装桌面接入补丁：

- `QQNT.dll`：`1ad441f56c9c1eb3cd24cac0e018a3c7fb58a7d8c40100c3790d28fb27e89611`
- `resources/app/package.json`：`24c7a457fae6b62474a3822bc4b39b9e418d3c2cf9e4e891b4ac94a47db29c80`

## 接口与行为

- `/api/qq/status` 明确区分桌面客户端占用、独立采集启动中、等待扫码、重复登录和进程检查失败。
- 普通桌面 QQ 运行时，自动停止本工作台的独立采集，撤销常驻标志；工作台重启也不会抢占登录。桌面退出后需人工开启采集。
- `/api/qq/start` 在桌面运行时返回 HTTP 409，不写入常驻开关、不启动另一个 QQ。命令行、Python 启动器都使用此接口。
- `/api/qq/stop` 等待已开始的启动完成后，再核对路径、父子关系和创建时间，通过 WMI 终止所拥有的采集进程，并查询确认。失败返回 HTTP 500，保留普通桌面 QQ。
- 采集启动器或 QQ 子进程仍运行、接口暂未就绪时，阻止重复拉起。
- 旧二维码不再向停止或冲突状态提供；扫码页显示真实接口错误，并提供“停止采集，使用桌面 QQ”。
- 日志增加桌面优先暂停与停止采集事件，不记录登录参数或完整命令行。

当前仍是独立采集方案。普通桌面 QQ 的账号无法从无补丁客户端直接共享给工作台；保护桌面登录期间，QQ 新消息采集及工作台发送暂停，微信、已保存消息和待办可以继续使用。检测按进程进行，因此也保护正在扫码、或使用其他账号的桌面 QQ。

## 验证

- 针对性测试覆盖进程归属、PID 复用、启动器退出但 QQ 尚在、桌面优先暂停、启动前复查、并发停止、错误 HTTP 状态、旧二维码拦截和真实 Windows 进程查询。
- 首次实机运行发现 Windows PowerShell 5.1 需要正确的 UTF-8 BOM；修正脚本编码后真实进程查询成功识别桌面 QQ，添加实际运行检查防止回归。
- 两个启动器在独立临时目录与模拟 HTTP 服务中完成验证。PowerShell 统一 UTF-8 输出，并读取 5.1 的错误响应正文；Python 在输入被重定向时不再等待回车。遇到 HTTP 409 都以失败状态退出、显示具体冲突原因、不创建常驻开关。隔离验证没有启动真实 QQ。
- 用户已确认恢复桌面 QQ 聊天主界面；修复后的自动检查只暂停独立采集，不能把此状态误报为工作台已自动接入桌面 QQ。
- 最终 `npm.cmd test`：51 项通过，0 失败、0 跳过；26 个 JavaScript 文件、Python 启动器及 Windows PowerShell 5.1 脚本语法检查通过。
- 本机服务已重启至 0.4.1。实际启动接口返回 HTTP 409，旧二维码接口返回 HTTP 409，停止接口返回 HTTP 200；停止前后桌面 QQ 的 PID 与创建时间相同。
- 登录页实际显示桌面优先说明，隐藏二维码，禁用冲突的启动操作。多个检查周期后仍只有原桌面主进程，`keepRunning=false`、`launcherRunning=false`、`ownedQQRunning=false`；微信在线，保存消息 80 条（历史补拉 79 条），待办 19 条，与重启前一致。
