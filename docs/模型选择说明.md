# 工作台的 AI 模型选择

调查日期：2026-10-11。

## AI 在工作台中做什么

接入程序负责接收 QQ 消息，工作台负责保存、筛选与显示；模型负责结合聊天上下文，判断通知、任务、负责人、截止时间及后续变更。

API 可以理解为“工作台向模型提问的接口”：程序把选定的消息发给模型，拿回结构化结果，用于生成任务。网页中能使用某个聊天产品，并不等于本地工作台已经取得该产品的程序调用凭据。

## 两种可选方式

| 方式 | 在线模型 API（如 DeepSeek） | 本机运行模型（如通过 Ollama） |
| --- | --- | --- |
| 准备工作 | 申请模型平台账号，配置 API 凭据和可用额度 | 安装运行工具并下载适合本机的模型 |
| 计算位置 | 模型服务商的服务器 | 用户电脑；需要明确使用本地模型而非云端模型 |
| 对本机配置的要求 | 无需在本机承担模型推理 | 内存、显卡和模型大小会影响速度与效果 |
| 数据发送 | 分析需要把选定聊天内容发送至服务商 | 本地部署时可把推理与聊天处理留在本机 |
| 成本 | 按实际输入、输出用量计费 | 本机硬件、存储、耗电及维护成本 |
| 适合的第一步 | 尽快验证通知识别效果 | 对消息留在本机有较强要求，且愿意承担模型部署 |

## 当前建议（尚待用户选择）

先使用本地工作台保存消息，配合在线 API 验证通知理解。这是基于搭建步骤和硬件需求作出的建议，不是已测得的模型效果结论。仅分析用户选择的学校群与好友；批量整理新消息，避免每条闲聊都调用模型。

截至本次查阅，DeepSeek 官方文档列出 `deepseek-flash` 等模型，并提供 JSON 输出能力及按用量计费的说明。具体模型、价格与效果应在配置和试用时复核。

如果用户更重视消息留在本机，则先核实电脑内存、显卡和可用空间，再选择本地模型。Ollama 同时提供本地与云端使用方式；只有确认使用本地模型和本机端点时，才应把方案描述为本地推理。

当前用户尚未选择模型服务；没有配置或保存任何真实凭据，也没有发生模型调用。

## 验证效果的方式

用脱敏的学校通知样例核验：识别作业、考试、报名和材料提交；判断是否与用户有关；关联后续修改；将不明确的日期和负责人标为待确认；所有结果均能查看原消息。
